## 同一个 AI 模型，为什么换个 API ID，费用可能差 4 倍？

做过 AI API 接入的朋友应该见过这种情况：明明没有调用多少次，额度却下得特别快。

排查时除了看Token，还应检查一件经常被忽略的事：**你到底请求的是哪个完整模型ID？**

拿2026年11月24日公开价格目录里的一组价格举例，同一个`claude-sonnet-5`有三种接入ID：

| 请求的model值 | 输入费率（⚡/百万Token） | 输出费率（⚡/百万Token） |
|---|---:|---:|
| `basic/claude-sonnet-5` | 2 | 10 |
| `standard/claude-sonnet-5` | 4 | 20 |
| `claude-sonnet-5` | 8 | 40 |

这不是模型能力的统一分级标准，而是**该目录中可用的三条接入线路及各自报价**。⚡表示所使用平台的额度消耗单位，别直接当成人民币；其他型号不一定有三条线路，也不一定都是1:2:4。

### 用一轮请求算清楚

假设实际一次请求包含5万输入Token和1万输出Token，暂不考虑缓存、长上下文、附加服务、特殊折扣等因素：

`费用 = 输入Token ÷ 1,000,000 × 输入费率 + 输出Token ÷ 1,000,000 × 输出费率`

- Basic：`50,000/1,000,000×2 + 10,000/1,000,000×10 = ⚡0.2`
- Standard：`50,000/1,000,000×4 + 10,000/1,000,000×20 = ⚡0.4`
- 无前缀：`50,000/1,000,000×8 + 10,000/1,000,000×40 = ⚡0.8`

同样一份示例工作量，**无前缀的目录扣费是Basic的4倍**。这不是一次真实付费请求的账单，而是根据公开费率做的等量演算。

### 真正让成本涨得快的，往往还有第二个因素

Agent、IDE助手和多轮对话很容易持续把前面的聊天记录、代码片段和工具输出重新附在下一次请求里。你输入“继续”可能只有两个字，但这一轮的`input_tokens`未必少。

所以不能单凭“今天发了几次请求”判断成本。至少记下四项：**完整model ID、input tokens、output tokens、实际平台扣费**。如果平台区分缓存读取、缓存创建或长上下文档位，也要把那部分单列。

### Basic要不要一直选？

若任务是普通试用、文本处理或初步方案，Basic是值得先比较的省额度选项，但偶尔可能有响应波动；实际可用性取决于线路和当时状态。Standard、无前缀费用高，不等于每次回答质量必然更好，也不等于一定更稳定。

我更倾向一个简单的顺序：**先拿小样本核实任务质量、延迟与账单，再决定正式任务的线路**。不要把整批任务直接开在没对过账的模型ID上。

### 开始前的三步自查

1. 确认客户端填写的`model`是完整值，不要不小心删掉`basic/`或`standard/`。
2. 对照每百万Token的**输入和输出**费率；复杂表达式、缓存及多模态计费另看规则，不要强行套用本文算式。
3. 先完成少量请求，检查实际用量记录和重试次数；发现出入先暂停批量任务排查。

我把这类完整线路ID和实际公开目录价格放在模型选型页面，方便查阅。选择API之前，先搞清楚“买额度便宜”和“每次调用消耗少”是两回事。
